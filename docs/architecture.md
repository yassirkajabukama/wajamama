# Wajamama architecture and integration truth

The Expo 57 app uses Expo Router screens in `src/app`, feature composition in `src/features`, reusable controls in `src/components`, and one demo provider. The entry gate routes splash → language → four intro slides → consent → phone sign-in → demo OTP → post-login welcome → service selection → home. Demo status and the sample-service disclaimer are explained in profile; action-specific safety notices stay near the relevant action. Demo booking, group posts, profile, check-in, selected care and liked articles share one state instance during the current app process. Sign-out clears that state and all demo bookings. No patient data is persisted on the device. Language, intro completion, tab-label display preference and versioned demo consent choices are stored on-device in SecureStore on native or localStorage on web; these choices are not a live account consent record. Sign-out clears consent choices but keeps language and intro completion.

The five Expo Router tab routes render through a custom floating React Native bar. Reanimated 4 animates its entrance, selection indicator and focused icon; system reduced-motion preferences are respected. The bar uses safe-area insets, platform shadow/elevation and keyboard dismissal behavior, while tab root screens reserve scroll space beneath it.

`src/lib/live.ts` is a guarded Supabase client and typed operation boundary. The mobile UI does **not** switch to it merely because `.env` is populated. A live mode rollout requires full session lifecycle, approved SMS service, migrated and tested database, operational staff tools, and an end-to-end booking pass; keeping the demo adapter attached avoids fictional live confirmations. Setting `EXPO_PUBLIC_DATA_MODE=live` blocks the demo UI with a clear unavailable message; the live client also rejects missing configuration. No service-role or provider secret belongs in mobile config. Auth sessions in this foundation are memory-only: secure persistence and account-switch recovery remain gates.

The database migration is an **unapplied development contract**. It creates separated auth user/patient/guardian records, RLS, service and booking tables, exclusion-constrained resource reservations, transactional RPCs, group care, learning, handoffs and an outbox. Migration SQL has not been validated against a running Supabase instance here. In particular, backend availability, guardian/staff authorization, notification jobs and cohort operation require integration and race tests before rollout. A staff queue is required for approvals, content review, moderation and contact requests. There is no admin UI in this task.

The assistant is an honest local example. Voice does not record or play audio. Live AI needs approved sources, consent and retention decisions, a server gateway, replaceable STT/AI/TTS adapters, and no client secret. Live push needs an authorized outbox worker, token lifecycle, privacy-safe lock-screen templates and device permission handling.

Every displayed service, duration, location, booking policy, group session and article is a **development fixture**, not clinic information. The only external links are to the user-provided official site and appointment page. No unverified staff, contact, price or schedule is presented as real. Default language is Kiswahili with optional English; clinical and local-language review remain release gates.

## Visual identity

The local `assets/wajamama-brand.png` was converted from the [clinic site](https://www.wajamama.com/) and is retained as a source asset, but the logo is not rendered in screens or the splash. The user-supplied five-swatch image defines the app palette, with `#5A189A` as the light-mode primary. See [theme.md](theme.md) for the single color source, Material 3 roles and iOS mappings. The attached handoff references still guide rounded cards, spacing, editorial learning cards and navigation. Confirm official brand asset usage and clinical content with Wajamama before release.

User-supplied Aptos Regular, Bold and Display Bold files from `assets/aptos/` are loaded through Expo Font at startup and used for body, controls and headings. Font file licensing for distribution remains a release check.
